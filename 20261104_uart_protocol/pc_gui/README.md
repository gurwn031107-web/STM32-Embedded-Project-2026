# Nucleo-F411 UART 제어 프로그램

STM32 Nucleo-F411 보드와 UART(바이너리 패킷)로 통신하여 LED 4개를 제어하고 온습도(DHT11)와 초음파 거리를 표시하는 PC용 GUI 프로그램입니다.

## 설치

Python 3.10 이상이 필요합니다.

```
pip install -r requirements.txt
```

설치되는 패키지는 PySide6(GUI), pyserial(시리얼 통신), pyqtgraph(실시간 그래프)입니다.

## 실행

```
python main.py          # 실제 보드 (포트 자동 감지)
python main.py --sim    # 보드 없이 가상 보드로 실행
```

`--sim` 모드는 보드 없이 GUI와 통신 흐름을 확인할 때 씁니다. 가상 보드가 실제 펌웨어처럼 응답하고, 거리값은 손을 앞뒤로 움직이는 것처럼 바뀝니다.

## 화면 구성

| 영역 | 기능 |
|---|---|
| 연결 | 포트 선택, 연결/해제, 자동 연결 켜기/끄기, 연결 상태 표시 |
| LED | LED0~3 토글, 전체 ON/OFF, 상태 읽기 |
| 센서 | 온도, 습도, 거리 표시. 자동 측정 주기 설정, 1회 측정 |
| 그래프 | 최근 60초의 거리, 온도/습도 |
| 통신 로그 | 송수신 패킷 HEX, 해석 결과, 오류 |

동작 규칙은 다음과 같습니다.

- **자동 연결:** ST-LINK 포트(VID 0x0483)에 `LED_STATUS_REQ`를 보내서 `0x94` 응답이 오는 포트에 연결합니다. USB를 뽑으면 연결 끊김으로 표시하고, 다시 꽂으면 자동으로 다시 연결합니다.
- **수동 해제:** "연결 해제"를 누르면 자동 연결도 함께 꺼집니다. 곧바로 다시 연결되는 것을 막기 위해서입니다.
- **LED 버튼:** 클릭하면 `…`(응답 대기) 표시가 되고, 보드가 OK로 응답한 뒤에 ON/OFF가 바뀝니다. 연결 직후에는 보드의 실제 LED 상태를 읽어 버튼에 반영합니다.
- **명령 처리 순서:** 요청은 하나씩 보냅니다. 응답이 오거나 300ms 타임아웃이 난 다음에 다음 요청을 보냅니다.
- **응답 없음 경고:** 연속으로 3번 타임아웃이 나면 연결 상태 옆에 "보드 응답 없음"이 표시됩니다.

## 통신 프로토콜

보드 펌웨어(`20261104_uart_protocol`의 `uart_protocol.c`)와 같은 형식입니다.

```
| SOF(0xAA) | LEN | CMD | PAYLOAD (LEN-1 바이트) | CHECKSUM |
LEN      = CMD 1바이트 + PAYLOAD 길이   (1~15)
CHECKSUM = (LEN + CMD + PAYLOAD 합) & 0xFF
```

설정은 115200bps, 8N1이며 Nucleo의 USART2(PA2/PA3)가 ST-LINK 가상 COM 포트로 연결됩니다.

### 요청 (PC → STM32)

| CMD | 이름 | PAYLOAD |
|---|---|---|
| 0x10~0x13 | LED0~3_SET | 0x00 = OFF, 0x01 = ON |
| 0x14 | LED_STATUS_REQ | 없음 |
| 0x20 | TEMP_HUMID_REQ | 없음 |
| 0x30 | DISTANCE_REQ | 없음 |

### 응답 (STM32 → PC)

| CMD | 이름 | PAYLOAD |
|---|---|---|
| 0x90~0x93 | LED0~3 응답 (요청 CMD + 0x80) | 결과 (`RSP_OK` 0x00 / `RSP_ERR` 0x01) |
| 0x94 | LED_STATUS_RSP | LED0, LED1, LED2, LED3 (각 0/1) |
| 0xA0 | TEMP_HUMID_RSP | 온도 정수, 온도 소수, 습도 정수, 습도 소수 |
| 0xB0 | DISTANCE_RSP | 거리 상위바이트, 거리 하위바이트 (cm, 빅엔디안) |

- LED 응답은 공용 `0x90`으로 와도 받아들입니다.
- 센서 응답이 `[0x01]`(RSP_ERR) 한 바이트로 오면 "센서 읽기 실패"로 표시합니다. 현재 펌웨어는 보내지 않지만 센서 오류 처리를 넣을 때 쓸 수 있습니다.
- PAYLOAD 길이가 표와 다르면 로그에 "길이 불일치" 오류가 표시됩니다. 펌웨어를 바꿨을 때 가장 먼저 확인할 곳입니다.
- DHT11은 최소 1~2초 측정 간격이 필요합니다. 펌웨어가 주기적으로 측정해 두고, 요청이 오면 저장된 최신값으로 응답하는 방식을 권장합니다.

### 예시 패킷

| 내용 | 바이트 |
|---|---|
| LED0 ON 요청 | `AA 02 10 01 13` |
| LED0 응답 (OK) | `AA 02 90 00 92` |
| LED 상태 요청 | `AA 01 14 15` |
| 온습도 요청 | `AA 01 20 21` |
| 온습도 응답 (21.1°C, 48.0%) | `AA 05 A0 15 01 30 00 EB` |
| 거리 요청 | `AA 01 30 31` |
| 거리 응답 (506cm) | `AA 03 B0 01 FA AE` |

## 파일 구성

| 파일 | 역할 |
|---|---|
| `main.py` | 프로그램 시작점 (`--sim` 옵션) |
| `config.py` | 보레이트, 타임아웃, 폴링 주기 등 설정값 |
| `protocol.py` | CMD 정의, 패킷 생성, 체크섬, 응답 해석 |
| `packet_parser.py` | 수신 바이트를 패킷으로 조립 (SOF 재동기화, 수신 타임아웃) |
| `serial_worker.py` | 송수신 스레드, 명령 큐, 응답 대기, 타임아웃 |
| `port_scanner.py` | 포트 목록 조회, 보드 확인(핸드셰이크) |
| `simulator.py` | 가상 보드 (`--sim` 모드와 테스트에서 사용) |
| `main_window.py` | GUI 화면 |
| `tests/` | 자동 테스트 (`test_firmware_compat.py`: 펌웨어 C 코드를 옮긴 모델로 호환성 확인) |

통신 부분(`protocol`, `packet_parser`, `serial_worker`)은 Qt를 쓰지 않습니다. 그래서 GUI 없이도 테스트할 수 있습니다.

## 테스트

```
pip install pytest
python -m pytest
```

`tests/test_pty_serial.py`는 리눅스/맥의 가상 터미널로 실제 pyserial 경로를 검사합니다. 윈도우에서는 자동으로 건너뜁니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 포트 목록에 보드가 없음 | USB 케이블이 데이터용인지, ST-LINK 드라이버(STSW-LINK009)가 설치됐는지 |
| "포트를 열 수 없습니다" | Tera Term, CubeIDE 시리얼 터미널 등 다른 프로그램이 같은 포트를 열고 있는지 |
| 포트는 보이는데 "보드를 찾지 못함 - 응답 없음" | 펌웨어가 실행 중인지, 보레이트가 115200인지, USART2를 쓰는지, `0x14` 요청에 `0x94`로 응답하는지 |
| 계속 "응답 없음" 타임아웃 | 로그의 TX 패킷이 펌웨어가 기대하는 형식과 같은지. 펌웨어가 체크섬 오류 패킷을 무시하고 있지는 않은지 |
| "길이 불일치" / "해석 실패" | 펌웨어 응답 DATA가 위의 응답 표와 같은지 (결과 바이트 위치, 거리 2바이트 등) |
| USB-UART 변환기(CP2102 등)를 쓰는 경우 | ST-LINK 포트가 아니라서 자동 감지 대상이 아닙니다. 목록에서 직접 선택하고 "연결"을 누르세요 |
